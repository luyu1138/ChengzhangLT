# OSS 每日加密备份

适用于成长蓝图 Android 1.1.2；旧版 1.1.0/1.1.1 使用原启用/暂停按钮。无需申请阿里云盘开发者应用。支持个人自用的专用 RAM AccessKey，不使用主账号密钥；尚未提供面向公众分发的 STS 授权服务。

## 1. 创建私有 Bucket

在阿里云 OSS 控制台创建标准存储 Bucket，选择合适地域，将访问权限设为私有并开启阻止公共访问。记录名称和地域，例如 `cn-hangzhou`。App 自动使用 `https://<bucket>.oss-<region>.aliyuncs.com`；当前只支持标准公网 Endpoint，不支持自定义域名、内网 Endpoint 或加速域名。

App 每次保存先提交本地数据库，不等待网络。启用备份后，Android JobScheduler 每天安排一次联网任务；首次开启自动备份及当天尚未成功备份时重新打开 App 会安排补试；手动备份单独安排，不依赖自动备份开关。周期任务与重试受 Android 电量、联网及系统调度限制，不保证固定时刻执行。强制停止、关机时不会运行，重新启动应用后恢复调度。任务使用可用网络，可能产生移动数据流量。

## 2. 创建最小权限 RAM 用户

创建只用于此 App 的 RAM 用户及 AccessKey，不要将主账号密钥用于手机。将以下策略中的 `YOUR_BUCKET` 替换为自己的 Bucket 名称后授权。App 不需要管理 Bucket、修改 ACL、列举其他文件或删除云端对象。

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["oss:PutObject", "oss:GetObject"],
      "Resource": ["acs:oss:*:*:YOUR_BUCKET/growth-blueprint/*"]
    }
  ]
}
```

回读校验需要 `GetObject`，只允许上传会使备份保持失败状态。使用控制台下载文件时，用自己的控制台账号操作，不要求 App 增加列举权限。需要进一步隔离时，可将策略缩小到具体工作空间/设备目录。

AccessKey Secret 不要发到聊天、写进 Git 或嵌入 APK。App 的设置页通过原生桥保存配置，凭据及恢复码使用 Android Keystore AES-256-GCM 加密并原子写入私有目录，不进入浏览器存储或导出的业务备份。这个个人自用方案仍会在手机上持有长期 RAM 凭据；向其他用户分发统一云服务时，应另行实现身份认证与 STS 临时授权，不能分发一组共享密钥。

## 3. 在 App 中配置与备份

进入“设置 → 阿里云 OSS”，填写 Bucket、地域、专用 RAM AccessKey ID 和 Secret。单独保存设置页生成的 43 位恢复码，勾选确认后点击“保存 OSS 配置”。首次保存默认关闭每日自动备份；已有配置再次保存会保留原开关状态。更换凭据时同时填写新的 ID 与 Secret；两项都留空会保留现有配置。

恢复码独立于手动导出的备份恢复码。它只在当前设备保存，应另存到自己管理的安全位置；卸载会丢失本机配置，恢复码丢失将无法解密已有云端文件。修改 Bucket/地域会继续使用本机现有恢复码；移除配置后重新设置会生成新的恢复码，旧文件仍需要旧码。

通过页面上方的“每日自动备份”开关开启或关闭自动上传，设置会保存在本机。开启后系统安排每日任务和漏备补试；关闭会取消自动任务，但不取消手动备份，也不删除云端已有文件。配置已保存时，无论开关是否开启，都可点击独立的“立即备份”。

保存配置、开启开关及安排立即备份均不表示上传成功。手动任务分别显示排队、上传校验、失败和成功；无网络时等待联网。上传并回读校验通过后，页面显示醒目的绿色“立即备份成功”提示、完成时间，并自动滚动到提示；关闭页面再打开仍可查看最近手动结果。再次手动备份会清除上一次成功提示，自动备份的成功时间不会冒充本次手动成功。上传结束后，App 用同一路径下载密文并比对 SHA-256；一致才记录成功时间、对象路径和备份修订号。错误、权限拒绝、重定向、回读不一致均不会更新成功标记。HTTP 重定向不会携带凭据跟随到其他地址。

## 4. 文件组织、费用和恢复

```text
growth-blueprint/<空间ID>/<设备ID>/YYYY-MM-DD.gbp
```

每天每台设备一份完整加密快照，包含所有人物及其目标、固定计划、完成实例、记录、附件和复盘。同日手动备份或重试会替换当天文件；各设备分别写自己的目录，不覆盖其他设备。旧日期文件不会自动删除；若 Bucket 开启对象版本管理，同日覆盖也可能保留多个计费版本。可在 OSS 控制台为指定备份前缀设置合适的生命周期，例如按需要保留 30 或 90 天，同时处理非当前版本。

每次实际备份产生一次 PUT 和一次完整 GET 校验，因此会产生上传/读取请求、存储和下行流量费用；同日手动重复备份会增加请求及流量。计费以实际地域和服务价格为准，建议设置费用预警。

恢复步骤：

1. 在 OSS 控制台下载正确空间、设备、日期对应的 `.gbp` 文件。
2. 打开新手机上的成长蓝图，进入“设置 → 备份恢复”。
3. 选择文件，输入该设备备份所用的恢复码。
4. 验证格式、认证标签、人物归属及附件摘要后，核对预览内容。
5. 先导出当前空间，再显式确认替换。不会静默合并两个设备的数据。

备份在本机先用独立 AES-256-GCM 密钥加密，再经 HTTPS / OSS V4 签名上传。它与 App 现有 `.gbp` 恢复格式相同，不依赖旧手机的 Keystore 解密。附件总量上限 10MB、单文件 5MB、加密备份文件 20MB；超限会提示失败并保留本机原数据。

## 5. 固定计划提醒

在“行动 → 添加固定计划”选择每日、每周指定星期或每月指定日，设置提醒时间。按人物时区计算，短月没有指定日期则跳过；每周 N 次计划在尚未满足次数且当天未完成时每日提醒。

Android 13+ 需允许通知；设置中可以查看通知和准时提醒状态。Android 12+ 可选允许“闹钟和提醒”特殊权限，否则使用系统非精确调度。关闭通知、限制应用后台、关机及强制停止会影响提醒。通用每日提醒与固定计划提醒分别设置；固定计划使用自己明确选择的时间，不套用通用提醒的 22:00–08:00 时间限制。

完成、撤销、暂停、归档或改期后会重算下一次提醒；已完成实例不会继续提醒。锁屏公开文案仅提示有一项计划到时，不显示人物和任务正文。点击通知进入对应人物、计划日期的行动页。完成记录按计划日期所属月份筛选，并另行显示实际完成时间；补做不会篡改原计划日期。

## 验收范围

原生 V4 签名已与阿里云官方 Java SDK 3.18.3 比对，传输使用本地 HTTP 测试服务检验，原生加密文件已通过实际 TypeScript 恢复校验。测试使用公开的虚构凭据，不连接真实 OSS。发布记录中的真机通知、真实账户上传/下载、跨日后台执行及换机恢复仍应按实际结果验收，不能仅凭“已启用”判断已完成备份。


## 403：如何确认 RAM 权限

配置已保存与请求授权是两个状态。若显示 HTTP 403，服务端拒绝了某次请求；仅凭 1.1.0 的统一文案无法确定根因。

1. RAM 控制台进入“身份管理 → 用户”，选中创建该 AccessKey 的用户。
2. 在认证/AccessKey 管理中，对照 App 使用的 AccessKey ID，确认属于这个用户且已启用。无需向他人提供 Secret。
3. 在用户的权限管理中查看直接授权及用户组继承策略，确认包含 Effect=Allow、Action=`oss:PutObject` 与 `oss:GetObject`、Resource=`acs:oss:*:*:YOUR_BUCKET/growth-blueprint/*`，其中 YOUR_BUCKET 必须替换为实际 Bucket 名称。
4. 自定义策略创建后还需要添加到该用户；仅创建策略不会产生授权。只读策略不能上传。已有完整 OSS 访问策略时，通常已覆盖这两项操作，不需要继续扩大权限。
5. 核对 Bucket 概览中的实际地域与 App 地域一致，并确认 ID/Secret 为同一对有效 RAM 密钥。已有 Allow 时，显式 Deny、Bucket Policy、访问来源限制等仍可能拒绝请求，应按实际错误码诊断。
6. 授权生效后，在 App 点“立即备份”。1.1.1 及后续版本会显示下面的信息；有成功时间才表示完成了回读校验。

| 显示的错误码 | 首先核对 |
| --- | --- |
| 上传 PUT + AccessDenied | 上传使用的 RAM 用户、目录 Resource、oss:PutObject，以及 Bucket 限制 |
| 下载校验 GET + AccessDenied | oss:GetObject；文件可能已上传，但回读未通过，本次不会标记成功 |
| InvalidAccessKeyId | AccessKey ID 是否有效、启用 |
| SignatureDoesNotMatch | ID/Secret 是否配对、地域是否正确；配置确认无误时，继续以请求编号排查客户端签名 |
| AuthorizationHeaderMalformed / InvalidRegion | Bucket 的实际地域代码 |
| RequestTimeTooSkewed / RequestHasExpired | 手机自动日期时间 |

若需进一步排查，可只提供新版显示的错误码、操作阶段和请求编号。不要发送 AccessKey Secret、恢复码或包含签名/请求原文的完整 OSS 错误响应。安装修正版时覆盖更新以保留本机数据与配置。
