# 成长蓝图个人成长管理 App 详细设计

版本 V1.0　｜　设计日期 2026年10月20日　｜　适用阶段 产品评审与研发拆解

本方案设计一款暂名“成长蓝图”的个人与家庭成长管理 App，将长期方向拆解为阶段成果和日常行动，再通过进度跟踪与复盘持续调整。首页直接展示每个人的动态卡片，成长档案、目标、记录及复盘的云端持久副本存储在用户授权的阿里云盘中，手机保留加密本地数据，支持离线使用。

建议首版采用 Android 优先、Flutter 跨平台架构，支持一个管理者维护多个成长档案以及同一管理者的多设备同步。独立成员账号、成员之间的细粒度共享放在后续版本。本文是完整设计方案，界面示例使用演示数据，接口尚未接入，性能值属于验收目标。

## 1 产品定位与范围

### 1.1 产品名称与价值

建议名称：成长蓝图。该名称为产品工作名，正式发布前再完成名称及商标核验。

产品主要回答四个问题：我希望成为什么样的人；当前阶段要取得什么成果；今天应该做什么；过去的投入是否带来了改变。支持管理自己、家人及经授权管理的其他人的成长信息，每个人的目标和记录相互区分。

核心体验是打开首页即可看到每个人的近期方向、阶段进展、今天的行动和需要复盘的事项。衡量成长以成果和可持续投入为主，不使用人物排名或单一“人生总分”。

### 1.2 首版假设

- 使用方式：一个管理者管理多个档案，默认创建“我”，可继续添加家人或其他档案。
- 设备与语言：Android 手机优先，简体中文；架构预留 iOS、平板，首版不承诺独立 Web 端。
- 容量目标：常见使用为 1 至 10 个档案，按 50 个档案及合计 10 万条行动、观察和复盘记录进行容量验证；这是产品测试边界，不是阿里云盘配额。
- 云端方式：一个工作空间绑定一个阿里云盘账号，保存该空间内获准同步的数据；首版不提供跨账号实时协作。
- 默认时区：Asia/Shanghai，用户可修改；所有日期统计按档案时区计算。
- AI：不作为首版必要依赖，目标拆解与复盘先采用可编辑模板和确定性规则。

### 1.3 需求对应关系

| 用户需求 | 设计落点 | 首版交付判断 |
| --- | --- | --- |
| 短期与长期成长规划 | 五年方向、年度成果、季度目标、月周行动 | 可从任一层开始，支持关联与追溯 |
| 进度跟踪与复盘 | 指标计算、节奏判断、周月季年复盘 | 记录更新后卡片自动刷新 |
| 参考十五五规划理念 | 方向、分解、重点项目、资源约束、评估调整 | 提供五年规划模板及修订历史 |
| 简洁且有目标感 | 四个主导航、人物卡片、明确下一步 | 核心操作通常不超过三次点击 |
| 多个人的信息与数据 | 独立 person_id、档案切换、归属校验 | 各人数据不串档 |
| 首页展示每个人动态 | 多人卡片列表、筛选、置顶、更新状态 | 无需进入二级页即可了解状态 |
| 联网并存储阿里云盘 | 官方授权、加密文件、增量同步、恢复 | 通过平台准入与接入实测后开放 |

首版不纳入社交社区、公开排行榜、金融交易、健康诊断、企业绩效考核和自动读取第三方账号数据。成长内容由用户主动维护。

## 2 十五五规划理念如何转化为产品

“十五五”对应 2026 至 2030 年。规划纲要强调长期方向与年度落实相衔接，并设置任务实施、监测和评估机制。[S1] 下表是本产品对规划方法的转化，不是国家规划对个人生活的规定，也不代表官方关联。

| 参考的方法 | 个人成长中的对应做法 | App 功能 |
| --- | --- | --- |
| 长期方向与阶段安排衔接 | 先确定未来方向，再确定今年成果 | 长期规划与年度目标关联 |
| 重视发展质量 | 同时记录投入与成果，关注实际能力变化 | 过程记录与成果指标分别展示 |
| 围绕重点组织实施 | 每阶段聚焦少量重要目标 | 默认推荐 3 个重点目标，可修改 |
| 目标任务分类推进 | 区分基本承诺与探索性挑战 | “基础目标”“挑战目标”标签 |
| 资源与任务相匹配 | 考虑每周可投入时间与现实条件 | 时间预算、超载提醒、资源记录 |
| 动态监测和阶段评估 | 定期看数据、找原因、调整方法 | 周复盘、季度检查、长期中期复盘 |
| 调整有依据且可追溯 | 修改目标时保留原计划及原因 | 目标版本、调整记录、阶段快照 |

默认提供“2026—2030 个人五年规划”模板，也允许从当前月份开始建立未来三年、五年或自定义规划。2026年10月新加入的用户，起始基线默认取实际建档日期，不把过去未记录的月份判定为落后。

首版推荐的成长领域为职业与事业、知识与技能、健康与生活、家庭与关系、财务习惯、兴趣与创造。用户可增删、改名或隐藏领域，不要求每个领域都有目标。财务习惯仅记录自定预算与学习行为，不自动生成投资建议。

## 3 角色与信息架构

### 3.1 区分账号与成长档案

账号代表谁在操作，成长档案代表记录属于谁，两者不能混用。首版一个管理者可以维护多个档案；添加一个家人档案不会自动给该家人创建登录账号，也不会向其发送消息。

| 对象 | 含义 | 首版能力 |
| --- | --- | --- |
| 工作空间 | 一组成长档案与一个云盘绑定关系 | 创建、备份、恢复、解绑 |
| 管理者 | 解锁并操作当前空间的人 | 管理所有档案和同步设置 |
| 成长档案 | 一个被记录人的数据集合 | 目标、行动、记录、复盘独立保存 |
| 已授权设备 | 同一管理者使用的手机等设备 | 独立授权、独立同步队列 |
| 独立成员账号 | 后续版本的不同登录主体 | 首版不开放 |

首版所有档案均对空间管理者可见。人物分组、隐藏卡片或切换档案只用于组织界面，不构成对同一解锁设备使用者的安全隔离。若需要家人各自登录并保护私密日记，应进入成员协作版本，并增加独立身份和密钥权限设计。

### 3.2 主导航

底部固定四个入口：首页、规划、行动、复盘。设置、云盘连接、数据导出和安全管理从首页右上角进入，避免占用一个主导航位置。

“首页”始终是多人总览。“规划”“行动”“复盘”顶部显示当前人物，点击人物名称可切换；行动和复盘额外支持“全部人物”筛选。编辑页及保存按钮附近必须显示所属人物，防止串档。

主要页面包括：多人首页、人物详情、档案编辑、规划总览、目标详情、目标创建、行动清单、快速记录、复盘中心、复盘编辑、同步中心、冲突处理、备份恢复和设置。

## 4 首页卡片与视觉设计

### 4.1 首页布局

从上到下依次为产品名称与设置入口、轻量同步状态、人物搜索与筛选、人物卡片列表、添加人物按钮、底部导航。首页不放欢迎大图或长说明，让人物动态进入第一屏。

手机采用单列卡片；平板可采用双列。390dp 宽度下左右留白 16dp，卡片宽度自适应，普通卡片约 250 至 290dp 高，大字体模式允许自然增高。首屏显示至少一个完整卡片及下一张卡片入口。

每张人物卡片包含以下字段：

| 区域 | 默认内容 | 点击后的动作 |
| --- | --- | --- |
| 身份行 | 头像或首字、昵称、关系标签、更多菜单 | 进入人物详情或管理档案 |
| 当前方向 | 一句话年度方向及所属年度 | 打开该人物的年度规划 |
| 目标进展 | “2026年度目标进度 62%”及进度条 | 查看指标构成和数据覆盖率 |
| 下一步 | 一项最需推进的行动或最近里程碑 | 打开行动或里程碑详情 |
| 今日行动 | “已完成 2/3”或“今天未安排” | 打开该人物今天的行动 |
| 近期记录 | 最新动态摘要、发生时间、记录者 | 进入动态记录 |
| 复盘提示 | 下一次复盘日期或“本周待复盘” | 进入相应复盘 |
| 快捷操作 | 记进展、看计划 | 打开轻量记录面板或规划 |

年度进度与今日完成数是不同口径，绝不将二者相加。未创建年度目标时显示“设置今年的重点”；数据不足时显示“待补充进度”，不能显示虚假的 0% 或健康状态。

### 4.2 演示卡片内容

“我”的卡片示例：年度方向“提升专业能力与交付质量”；年度目标进度 62%；今日行动 2/3；下一步“完成模块验证清单”；最新动态“完成一次技术复盘”；复盘提示“周日待复盘”。

“家人A”的卡片示例：年度方向“建立稳定的阅读与生活节奏”；年度目标进度 40%；今日行动 1/2；下一步“本周阅读分享”；最新动态“记录阅读心得”。这些均为演示内容，不能作为真实个人数据导入。

### 4.3 排序与状态

默认顺序为用户置顶后按自定义顺序排列。可切换“最近更新”“需要关注”；不按人物成长百分比排名。需要关注按同步冲突、过期关键里程碑、待复盘排序，同时给出具体原因。

目标状态使用“按计划”“需关注”“待更新”“已完成”加文字和图标表达。红色只用于同步失败、删除确认或明显逾期等需要行动的事项，不渲染整个人物卡片为失败状态。

### 4.4 视觉规范

| 项目 | 设计规格 |
| --- | --- |
| 背景 | 浅灰 #F6F8FA，卡片白色 #FFFFFF |
| 主色 | 深青绿 #166B60，用于主按钮与进度 |
| 正文 | 深灰 #172B34，辅助文字 #60717C |
| 提醒 | 深琥珀 #8A5A00，错误 #B93832，并配文字 |
| 字号 | 页标题 24sp，卡片昵称 18sp，正文 16sp，说明 14sp |
| 间距 | 8dp 为基础，页面边距 16dp，卡片内边距 16dp |
| 圆角 | 卡片 16dp，按钮 12dp；弱阴影或浅色边框 |
| 触控 | 可点击区域不小于 48×48dp |
| 动效 | 保存与进度变化使用短动效，尊重系统减少动态效果设置 |

界面正文使用自然语言，例如“这周想推进什么”“遇到什么阻碍”“调整下周安排”。数据库版本、加密算法等细节只放在设置及技术信息页。

### 4.5 必备空态与异常态

首次使用无档案时展示“建立我的成长档案”；有档案无计划时展示“先选一个近期目标”；无今日安排时展示“今天未安排”，允许休息。无网络时保留卡片内容并注明本地数据时间；某个人物进度计算失败时仅该卡片降级，不阻塞整个首页。头像加载失败以昵称首字替代。

## 5 人物档案设计

档案必填字段为昵称，长度 1 至 30 个字符。可选字段包括关系标签、头像、年龄段、简介、成长关注点和时区。首版无需身份证、手机号、精确出生日期、学校或单位地址。每个档案具有不可变 person_id，同名档案允许存在，并通过头像与备注区分。

人物详情依次展示长期方向、当前重点目标、最近 30 天活动、阶段趋势、复盘记录和附件。不同领域分区折叠，默认只展开当前重点。

档案支持新增、编辑、置顶、排序、归档、导出和删除。归档后从首页隐藏，历史记录保留；归档会暂停未来提醒与新任务实例生成。删除进入 App 内回收站，默认保留 30 天；彻底删除需展示影响范围，包括相关目标、行动、复盘、附件和历史备份的处理选项。

用户创建他人档案时应明确自己具有记录和管理相关信息的授权；涉及儿童时采用监护人管理方式及适龄的参与机制。是否可将这些档案同步到阿里云盘，还需满足平台对该应用场景的确认，不能仅凭一个本地勾选框认为平台限制已解除。

## 6 长短期规划与目标设计

### 6.1 时间层级

| 层级 | 核心问题 | 推荐数量 | 主要输出 |
| --- | --- | --- | --- |
| 长期方向 | 未来三至五年希望有什么改变 | 3 至 5 个方向 | 愿景、现状、长期成果 |
| 年度目标 | 今年取得哪些可验证成果 | 3 至 5 个重点 | 年度指标与重点项目 |
| 季度目标 | 接下来一个季度推进什么 | 1 至 3 个重点 | 里程碑与关键结果 |
| 月度安排 | 本月形成哪些交付 | 按实际容量 | 行动组合与时间预算 |
| 周与日行动 | 下一步具体做什么 | 每日重点默认最多 3 项 | 可执行任务与记录 |

推荐数量是提示，不是不可修改的硬限制。用户可以先建周目标，再补充长期方向；系统不会要求填写全部层级。月度和周度一般作为排程视图，不必建立重复的目标树节点。

### 6.2 目标创建流程

先选人物与领域，再填“希望实现什么”和目标周期，随后确定验收方式，最后添加一个近期行动。首屏必填只有人物、目标名称、起止日期及验收类型，其他字段折叠为高级设置。

| 字段 | 规则 |
| --- | --- |
| 标题 | 1 至 80 字，使用结果表达，例如“独立完成一个模块的设计与验证” |
| 所属人物 | 必填且全过程可见；含记录的目标不能直接改到其他人物 |
| 所属规划及父目标 | 可选，同一人物内关联，禁止循环依赖 |
| 目标周期 | 开始日期不得晚于截止日期，子目标原则上落在父周期内 |
| 基线与目标值 | 数值型必填，记录基线日期、单位及数据来源 |
| 验收方式 | 数值、里程碑、频次或自定义量表，必须选一种主口径 |
| 类型与重要性 | 基础目标或挑战目标；重点标记；权重可配置 |
| 资源约束 | 每周可投入时间、需要的支持、可选费用预算 |
| 预期节奏 | 线性、里程碑计划或暂不判断 |
| 更新周期 | 每周、每月或自定义；用于待更新提示 |
| 证据 | 可选文字、图片、PDF 等；高重要性成果可设为必需 |

目标创建后进入草稿；确认后激活。完成条件达到后显示“可验收”，由用户确认成果再标记完成。状态包括草稿、进行中、暂停、已完成、已终止、已归档；“需关注”是计算标签，不是额外生命周期状态。

### 6.3 基础目标与挑战目标

基础目标是用户明确希望保证的最低成果，挑战目标是额外探索。二者各自显示完成情况，不因挑战目标未达成而把整体判为失败。卡片默认使用当前年度已纳入统计的目标集合，并明确显示是否包含挑战目标。

### 6.4 重点项目与版本调整

复杂目标可以创建重点项目，项目中维护里程碑、依赖、交付物和阻碍。任务完成属于执行证据，项目成果仍按自己的验收口径判断。

修改截止日期、基线、目标值、权重、验收方式或统计范围时，必须记录修改原因、生效时间、原值和新值。历史复盘绑定原版本，不随新目标偷偷重算。调整影响从生效时间开始；用户可在详情里查看“调整前”“调整后”。

暂停目标时停止未来提醒，保留原截止日期，恢复时由用户选择是否顺延。终止目标要求简短原因，保留已投入和历史成果。归档只影响展示，不删除历史。

## 7 行动执行与快速记录

行动分为一次性任务和重复习惯。一次性任务包含人物、标题、关联目标、计划日期、可选截止时刻、预计耗时、状态和备注；重复习惯另外包含重复规则、每周期次数、单次要求及暂停区间。

从人物卡片点击“记进展”后，可以记录完成行动、指标数值、里程碑成果或简短心得。默认继承当前人物和最近目标；切换人物会清空不兼容的目标关联。保存后立即刷新本地数据，云端同步状态单独显示。

重复规则首版支持每日、每周指定星期、每周 N 次、每月指定日和自定义间隔。每个实例使用“习惯 ID＋规则版本＋周期／日期”构成唯一标识。修改规则默认只影响未来实例；历史打卡保留原规则。

每周 N 次习惯按整周目标计算，不在周一就提示缺少其余次数；若安排了具体日期，则可以判断这些已到期实例。未来实例不进入到期完成率。默认不支持跨天多次重复计数，确有需要时显式打开“每天允许多次”。

逾期任务可选择今天继续、重新排期、暂停或终止。重新排期保留原计划日期和改期次数，避免通过改期美化历史数据。已完成任务可以撤销，撤销写入修订记录，并触发汇总重算。

记录同时保存事件发生时间与录入时间。补录默认允许，界面标注“补录”；周复盘锁定后发生的补录不改变原报告，而是生成重算版本供用户选择。

提醒默认由设备本地通知承担。支持每日摘要、任务前提醒及复盘提醒，默认安静时段 22:00 至次日 08:00。多设备可指定一个提醒主设备，其他设备默认不重复通知；通知权限被拒绝时，在 App 中显示待办，不反复弹窗。

## 8 指标计算与进度口径

### 8.1 分开衡量成果与行动

成果进度回答“距离目标结果还有多远”，行动完成率回答“计划做的事情完成了多少”。完成很多小任务不能自动证明长期目标已经实现。一个任务关联多个成果时可显示多处证据，但同一个原始事件不能被重复累计为同一指标的两次贡献。

数值在内部保留足够精度，界面百分比四舍五入为整数，判断状态时使用未四舍五入的值。比率均限制在 0% 至 100%，超额部分用“实际值／目标值”另行展示。

### 8.2 单项指标

| 类型 | 计算规则 | 示例 |
| --- | --- | --- |
| 数值增长型 | 进度等于 当前值减基线，再除以目标值减基线 | 基线 0、目标 12、当前 5，进度 41.7% |
| 数值降低型 | 进度等于 基线减当前值，再除以基线减目标值 | 基线 10、目标 2、当前 6，进度 50% |
| 里程碑型 | 已验收里程碑权重之和，除以全部里程碑权重 | 权重 20、30、50，完成前两项为 50% |
| 频次型 | 已完成有效次数，除以该周期计划次数 | 本周完成 2 次，目标 3 次，进度 66.7% |
| 自定义量表 | 使用预先定义的等级和对应分值 | 0、25、50、75、100，必须说明每级标准 |

数值增长型要求目标值大于基线，降低型要求目标值小于基线。目标等于基线的输入应被拦截，建议改用达标／维持类指标；维持类在首版按每个观察周期是否达标转为频次统计。负值和单位转换需要领域允许，不进行隐式单位换算。

累计指标对有效增量求和；状态指标取观察时间最新的一次有效测量。补录的较早观察值不能覆盖更新的状态测量。同一指标相同观察时点存在不同值时进入冲突处理，不能任意取设备时间较晚者。

### 8.3 目标与年度汇总

一个目标只能选择“按自身关键结果汇总”或“按子目标汇总”作为主进度来源。前者按指标权重加权，后者按直接子目标权重加权。父子链路不同时计入年度集合，防止重复计算。

年度进度等于该年度统计集合中各目标进度乘各自权重后求和，再除以权重总和。权重必须大于 0，界面可显示归一化后的百分比。例：三个年度目标进度为 80%、50%、40%，权重为 50%、30%、20%，年度进度为 63%。

只有统计集合所需的指标均有效时，首页才显示完整年度百分比。数据缺失时，可显示“已知目标进度 70%，数据覆盖 60%”，并将主要状态设为“待补充”；覆盖率按有效指标或目标的权重占比计算，不能把缺失数据直接当 0。没有更新但有历史值时仍显示最近进度，同时标注数据过期。

年度统计集合在发布计划时固定，完成的目标仍保留；新增、移除、暂停或终止造成的范围变化通过计划修订记录生效。默认暂停只影响执行提醒，不自动从统计集合移除。用户决定移除时须展示调整影响，历史快照不变。

### 8.4 行动完成率与执行节奏

今日行动完成率等于今天有效计划实例中已完成数量，除以今天有效计划实例总数。昨天遗留任务单列为“逾期待处理”，除非用户明确重新排期，不混入今天分母。

周行动完成率默认基于本周已到期实例，不包含未来安排；周视图同时显示本周总计划。已取消且尚未开始的实例不计入执行率，但在变更历史中保留取消数。到期后取消不回写历史分母，避免取消行为掩盖未完成。

对适合线性增长的目标，预期进度按开始日到截止日的实际经过时间计算；暂停期间是否停表由版本设置明确。里程碑目标以已到期里程碑的计划权重判断，不按时间直线推算。未设置节奏或数据不足时只显示实际进度。

默认“需关注”条件为：数据有效且实际进度落后预期超过 15 个百分点，或关键里程碑已逾期。阈值可调整。这是计划偏差提醒，不是对个人能力或健康的判断。

## 9 复盘机制

### 9.1 复盘节奏

| 周期 | 主要问题 | 系统预填 | 用户输出 |
| --- | --- | --- | --- |
| 每日可选 | 今天推进了什么 | 今日行动与记录 | 一条收获或阻碍 |
| 每周 | 行动是否有效、下周做什么 | 已到期完成率、成果变化、阻碍 | 保留、调整、下周重点 |
| 每月 | 时间投入是否符合重点 | 领域投入、指标趋势、改期情况 | 月度调整与资源安排 |
| 每季度 | 阶段成果是否支持年度方向 | 关键结果、里程碑、风险 | 目标修订或下一季度计划 |
| 每年 | 哪些能力和成果真正积累 | 年初基线、年末结果、重大成果 | 年度总结与下一年重点 |
| 长期中期与期末 | 方向是否仍适合当前生活 | 多年度成果与规划版本 | 继续、收缩、转向或升级 |

周复盘默认周日 20:30 提醒，可关闭或修改；默认时区为档案时区。不同人物独立生成复盘，管理者首页汇总待复盘数。

### 9.2 复盘表单

表单先展示本期事实，再填写四项：最有价值的进展；主要阻碍及原因；哪些方法要保留或停止；下周期最多三个重点。自由文字可选，首版提供简短选项帮助快速填写。

复盘保存为草稿或发布。发布时冻结目标版本、原始记录引用、统计区间、计算版本、时区与生成时间，保证之后能够解释数字来源。用户可以创建修订版，原版本保持可见。

“转为下周行动”先生成待确认列表，用户确认人物、日期和目标关联后保存。系统不自动延长目标、不自动提高任务量。用户选择休整时允许减少计划。

导出支持单人物、单周期的 PDF 阅读版和 Markdown 可编辑版；完整迁移采用加密备份包。导出前提供人物和日期范围预览，避免混入其他人的数据。

## 10 主要用户流程

### 10.1 首次使用

打开 App 后可先建立“我”的档案，选择一个成长领域，填写一个近期目标和首个行动，随即进入人物首页。阿里云盘连接可以在首次设置或之后完成。连接前明确显示“仅保存在本机”，不能出现“已备份”。

首次连接阿里云盘时，显示要同步的数据类型、所需授权和加密恢复方式；用户完成官方授权后选择新建空间或恢复已有空间。初始化生成密钥，用户保存恢复材料后开始首次上传。若暂不保存恢复材料，应明确显示换机恢复尚未就绪。

### 10.2 一次日常使用

在首页找到人物卡片，点击“记进展”，完成行动或录入成果，再返回首页看到更新。正常情况下只需两至三次点击。显示“已保存在本机”，待云端确认后再显示“已同步至阿里云盘”。

### 10.3 一次计划调整

从目标详情选择调整，查看原目标及已完成情况，填写新值与原因，预览对进度和后续行动的影响，再确认生成新版本。原行动不自动批量改期；用户可以在影响预览中逐项选择。

### 10.4 换机恢复

新设备安装后完成本人阿里云盘授权，选择工作空间，输入恢复密钥或由已解锁旧设备安全迁移密钥，校验快照与日志，再在临时数据库中重建数据。确认人数、记录数、最后同步时间无误后切换为正式空间。云端登录成功本身不能替代解密密钥。

## 11 阿里云盘接入方案

### 11.1 已确认能力与上线前置项

阿里巴巴发布的阿里云盘 SDK 文档列出授权、文件列表、上传、下载等能力，并给出 PKCE 等授权方式。[S2] 开发者服务协议要求入驻审核，实际可用功能受获批权限约束。[S3] 因此接入方案有技术依据，但不能在未获得本应用权限前承诺可立即上线。

公开开发者协议对敏感个人信息及提供其他用户个人信息有约束。多人成长档案与该约束的适用关系需要平台确认；获得被记录者同意和对文件加密，都不能自动替代平台许可。正式启用多人物云同步前，须取得该应用场景的准入结果，并保存适用协议版本和确认记录。[S3]

接入验证使用演示数据，核查：开发者资格、应用审核、Android／iOS 原生授权方式、允许的 scope、文件夹读写、上传完成与下载校验、刷新令牌行为、分页和限流、配额与费用、撤销授权、删除及恢复行为。费用和限额以实际获批应用控制台及当期规则为准，不写死为永久免费。

这里对接的是用户的阿里云盘个人存储空间。阿里云 OSS、PDS 是其他产品路线，不视为同一个账号或空间，也不在未说明的情况下替代用户指定的云盘。

### 11.2 首选授权结构

首选原生应用 OAuth 授权码加 PKCE，通过系统浏览器或官方支持的授权界面完成登录，不采集云盘密码。使用 state 校验回调，优先采用已验证应用链接；回调地址须预先登记。[S2][S5]

授权成功后令牌只进入操作系统安全存储；访问令牌和刷新令牌不写入成长数据包、日志或导出文件。每个设备独立授权，不复制另一台设备的刷新令牌。刷新采用单航班控制，避免同一设备多个请求同时刷新导致令牌轮换失败。

SDK 文档表明存在 PKCE 能力，但具体获批应用及 Android 接入路径仍须实测。若获批方式要求 client_secret，则使用最小授权代理服务交换令牌，绝不把 secret 写入 APK。该服务只处理授权必要信息与最少日志，不保存成长记录或附件。是否保管刷新令牌由获批流程确定并在隐私说明中写明。

尽量申请最小权限；若平台只能授予全盘文件读写 scope，授权页要如实说明。App 逻辑上限制在选定应用目录操作，但这种目录约束不是云盘服务端的细粒度权限隔离。首版不主动浏览或上传其他目录文件。

### 11.3 数据存放方式

阿里云盘保存加密后的业务数据、操作日志、附件和恢复快照；本机数据库负责查询与编辑。云盘作为文件同步与备份介质，不承担 SQL 查询、记录级事务或实时协作服务。

| 建议路径 | 内容 | 规则 |
| --- | --- | --- |
| GrowthBlueprint／空间UUID／bootstrap.json | 格式版本、随机空间ID、加密参数、封装后的空间密钥 | 不含姓名、目标正文或令牌 |
| 同目录／objects／随机ID.bin | 加密附件与大文本对象 | 不可变对象，上传后校验 |
| 同目录／events／设备ID／批次UUID.bin | 加密操作批次 | 只追加，禁止跨设备覆盖 |
| 同目录／snapshots／快照UUID.bin | 加密一致性快照及日志覆盖水位 | 可独立校验与恢复 |
| 同目录／commits／提交UUID.json | 对已完成对象的提交清单 | 含对象ID、密文摘要、长度；不含业务内容 |

以上为产品自定义文件组织方案，不是阿里云盘官方固定目录。文件与文件夹使用平台返回的 drive_id、file_id 寻址，路径用于展示。文件名使用随机标识，避免泄露人物昵称与目标标题。

用户在云盘中看到的是加密文件，不能直接预览成长正文。若需要可读报告，通过 App 显式导出；明文报告是否另存到云盘由用户选择。

## 12 离线与同步协议

### 12.1 本地优先写入

每次业务写入在一个本地数据库事务中同时更新业务实体并写入待同步 outbox。事务成功即提示本机保存成功；事务失败则不能显示成功。Repository 层统一处理数据读写，界面不直接调用云盘接口。[S4]

首页从本地数据库订阅更新，即使无网络也能读取档案、完成行动、更新目标和写复盘。重新联网后增量同步。系统在启动、回到前台、手动下拉、保存后合并延迟以及系统允许的后台任务中尝试同步；不承诺手机后台持续在线。[S6]

### 12.2 一次同步的步骤

1. 确认工作空间、云盘用户身份、权限和可用令牌；一个设备同一空间仅运行一个同步任务。
2. 分页扫描提交清单，结合设备水位与最近列表缓存识别新批次；缺失父版本或序号有空洞时暂不应用依赖操作。
3. 下载新对象，校验长度、密文摘要和认证标签，在本地事务中应用；同步游标与已应用 op_id 一起提交。
4. 将本地 outbox 合并为不可变批次，按唯一 ID 上传附件、事件和快照。所有引用对象完成上传并验证后，最后上传提交清单。
5. 云端可读取并验证提交清单及引用对象后，才将相关 outbox 标记已上传。超时结果不确定时先查询原提交 ID，不盲目创建新业务操作。
6. 再次拉取远端变化并重算受影响卡片。显示最后成功同步时间、待上传数量、冲突数量和附件状态。

该设计不依赖云盘支持文件原子替换、数据库锁或条件写入。提交清单自身也是不可变文件；崩溃前只上传了一部分对象时，未提交对象不会进入业务视图。扫描必须处理分页和目录枚举延迟，定期完整核对，不能把一个可覆盖的“最新版本文件”作为唯一真相。

### 12.3 操作结构与冲突

每条操作至少包含 op_id、space_id、person_id、entity_id、device_id、device_seq、schema_version、operation_type、父版本集合、修改字段、业务发生时间、记录时间及载荷。设备序号在本地事务中持久递增，重装设备生成新的 device_id，避免序号复用。设备墙钟仅用于展示，不作为冲突胜负依据。

| 并发情况 | 合并原则 | 用户体验 |
| --- | --- | --- |
| 不同人物或不同实体被修改 | 可独立合并 | 自动更新 |
| 同实体不同独立字段修改 | 基于共同父版本做字段合并，再校验业务约束 | 通过校验后自动合并 |
| 标题、日期、权重等同字段不同值 | 保留两个版本，不静默覆盖 | 展示本机与另一设备版本并选择 |
| 两设备完成同一任务实例 | 以实例唯一键与事件 ID 幂等合并 | 完成数量只增加一次 |
| 一端完成另一端撤销 | 识别并发状态冲突 | 用户确认最终状态 |
| 累计记录是不同真实事件 | 按独立 record_id 累加 | 可查看各次来源 |
| 删除与编辑并发 | 默认保持删除，编辑保存在待恢复分支 | 可恢复后选择保留修改 |
| 同期复盘并发编辑 | 保留草稿分支和已发布版本 | 用户合并后发布新版本 |

有冲突的目标继续显示最后无冲突版本及“待确认”，不把未确认数字混入正式汇总。解决冲突会生成同时引用冲突父版本的新操作，其他设备获得该操作后收敛。

### 12.4 重试与错误处理

网络错误采用指数退避和随机抖动，初始可设为 2 秒，逐步至 5 分钟，连续失败后交由后台调度或用户手动重试。429 优先遵从服务端 Retry-After；401 只尝试一次受控刷新，失效后进入“需重新授权”；403 检查权限或应用状态；空间不足暂停上传并保留全部本地待同步数据。

单文件失败不阻塞不依赖它的其他人物数据，但引用该附件的操作需保持“附件待同步”状态。未完成必要附件的记录不得被宣称已完整备份。失败提示包含原因、待同步数量和可执行按钮，不直接展示令牌或签名下载地址。

### 12.5 快照与日志保留

首版默认每完成一天的有效同步或累计 500 条已提交操作生成一次快照，阈值可配置。保留最近 30 个日快照、12 个月度快照及用户手动快照；这是应用策略，不依赖云盘自动版本功能。

快照保存已纳入的设备序号水位、未解决冲突、实体版本、删除标记和计算规则版本。首版不自动清理尚需恢复的操作日志。未来做日志压缩时，只有在快照通过恢复验证且所有保留设备确认水位后才清理；超过离线保留窗口的设备必须全量重建，禁止用旧日志复活已删除数据。

## 13 安全与数据生命周期

### 13.1 加密与密钥

建议本地使用加密 SQLite，云端内容使用成熟密码库提供的 AES-256-GCM 等认证加密。每个对象使用独立随机 nonce，密钥和 nonce 组合不能重复；将空间 ID、对象 ID、格式版本等不可变头作为认证附加数据，防止对象被调换。算法与库版本在实现阶段锁定并做安全复核。

空间内容密钥由系统安全随机源生成。设备通过 Android Keystore 或 iOS Keychain 保护本地密钥；云端只保存经恢复密钥封装的空间密钥。恢复材料可采用含校验码的高熵恢复码或加密恢复文件，不能以短 PIN 直接加密云端数据。

忘记 App 解锁 PIN 时，可通过安全存储中的设备认证策略或恢复材料处理。若所有设备和恢复材料都丢失，运营方不能恢复端到端加密内容。这个后果需在首次云备份前清晰说明，并提供一次恢复验证流程。

默认关闭敏感内容云端日志和明文系统自动备份；截图与系统任务切换缩略图可按隐私设置遮挡。开启生物识别只是设备解锁便利方式，不替代云端授权或恢复密钥。

### 13.2 绑定与设备管理

云盘账号变更时必须暂停同步，比较稳定账号标识并展示差异，不能将当前空间自动上传到另一个账号。用户可以选择新建空空间、显式迁移或取消。解绑默认仅清除授权，保留本机数据和云端文件；删除云端数据是单独操作。

设备列表记录设备昵称、首次授权和最后同步时间。撤销设备只能阻止其后续获授权访问，无法远程抹除已经下载的明文或密钥。若原设备持有空间密钥且存在泄露风险，需要轮换空间密钥并在其他设备重新授权恢复，旧密钥可解密的历史副本仍需按实际保留情况处理。

### 13.3 导出删除与恢复

完整备份包包括格式版本、实体数据、记录、目标版本、复盘快照、附件清单、摘要及加密封装信息。导入先在临时空间校验，不直接覆盖当前数据；用户预览后选择作为新空间恢复或执行经确认的迁移。

默认使用加密导出。用户显式选择明文 Markdown、CSV 或 PDF 时提示包含哪些人物和字段。CSV 导出需防止表格公式注入；文本和附件导入需限制文件大小、路径与类型，防止恶意内容破坏本地环境。

档案进入回收站后写入删除标记；恢复通过新操作显式完成。永久删除先停止相关写入，确认影响范围，清理本机实体及 App 管理的云端对象。旧快照或导出可能仍包含该人物的数据：若用户选择彻底清理，必须重建不含该人物的保留快照并清理旧对象；未能完成的云端清理显示待处理，不能宣称已删除。

应用不能保证删除用户手工复制的文件或第三方自行保留的副本，删除页应区分 App 管理范围与外部副本。

## 14 技术架构与模块边界

推荐客户端采用 Flutter 与清晰的分层结构。页面层只负责展示和交互；应用服务层组织用户流程；领域层负责目标、指标与复盘规则；数据层提供本地数据库、文件和云盘适配。依赖具体版本在技术验证后锁定，不以本文日期推定某个 SDK 必然可用。

| 模块 | 职责 | 关键边界 |
| --- | --- | --- |
| ProfileService | 人物档案与归档管理 | 强制 person_id 归属校验 |
| PlanningService | 规划树、目标版本与里程碑 | 防循环、范围与版本一致性 |
| ActionService | 任务、习惯实例、完成与撤销 | 实例幂等与日期规则 |
| MetricEngine | 指标、权重、覆盖率及偏差计算 | 纯规则计算，可重放 |
| ReviewService | 周期快照、发布与修订 | 冻结引用与计算版本 |
| DashboardService | 人物卡片的本地聚合数据 | 不逐卡远程请求 |
| SyncEngine | outbox、拉取、合并与提交 | 不依赖云盘原子覆盖 |
| CloudDriveAdapter | 官方授权、文件与限流适配 | 不把厂商字段扩散到业务层 |
| CryptoService | 加密、密钥封装与认证校验 | 不在业务日志输出秘密 |
| BackupService | 快照、导出、导入与恢复验证 | 临时恢复后再切换 |

Android 后台工作使用系统支持的持久任务机制，iOS 后台同步在适配阶段使用平台允许的任务方式。前台手动同步作为确定性入口；前台保存成功与后台上传成功使用不同反馈。[S6]

首版若获批直接 PKCE 接入，可不自建业务数据服务器。可选的授权代理、版本配置或故障统计服务必须最小化数据，不保存目标和复盘正文。后续引入 AI 分析时，需用户单独选择发送范围，不能默认把云盘中的全部数据交给模型服务。

## 15 核心数据模型

### 15.1 通用字段

可同步实体统一包含 id、space_id、person_id（空间级实体除外）、created_at、updated_at、schema_version、revision_id、parent_revision_ids、created_by_device 和 deleted_at。时间戳使用 UTC，业务日期另存 local_date 与 IANA 时区；日期型截止时间不因手机出差换时区而自动改变。

| Workspace | id、owner_subject、drive_binding、timezone、key_version | 一个有效云盘绑定 |
| Person | id、space_id、nickname、relation、avatar_ref、timezone、archived_at | 所有个人记录归属于一人 |
| Plan | id、person_id、horizon、start_date、end_date、vision、version | 同周期可有历史版本，只有一个当前版 |
| Goal | id、person_id、plan_id、parent_goal_id、title、status、aggregation_mode | 禁止跨人物父子关系及循环 |
| GoalVersion | goal_id、version、baseline、target、unit、weight、effective_at、reason | 关键参数不可原地覆盖历史 |
| KeyResult | id、goal_id、metric_type、aggregation_rule、weight、freshness_days | 只允许一种主计算口径 |
| Milestone | id、goal_id、due_date、weight、acceptance、accepted_at | 只有验收后计入成果 |
| Action | id、person_id、goal_id、type、schedule、estimate_min、status | 一次性任务或习惯定义 |
| ActionInstance | id、action_id、rule_version、period_key、planned_date、status | 同一规则实例唯一 |
| Observation | id、person_id、kr_id、event_time、recorded_at、value、source、supersedes_id | 改正保留旧记录，显式替代 |
| Review | id、person_id、period、status、revision、snapshot_ref、content | 同周期一个当前发布版，可有历史版 |
| Attachment | id、person_id、owner_entity_id、mime、size、cipher_hash、cloud_file_id | 记录元信息，正文存加密对象 |
| SyncOperation | op_id、device_id、seq、entity_id、parents、patch、state | op_id 唯一，设备序号单调 |
| Snapshot | id、watermarks、schema_version、calc_version、hash | 包含删除标记与冲突信息 |

## 17 非功能要求与验收

### 17.1 性能与可用性目标

在约定的 Android 中端测试机、release 构建及 50 人物／10 万记录测试集下，目标为：已有本地数据的冷启动首屏 P95 不超过 2 秒，人物切换 P95 不超过 300 毫秒，本地保存反馈 P95 不超过 200 毫秒。具体硬件与测量方式在测试计划固定，不能以开发机结果替代。

普通人物卡片使用本地预聚合，避免每次打开都扫描全部历史；新增记录只重算相关人物与目标。附件按需下载，默认单个附件上限可设为 20MB，属于本产品初始策略，最终须在平台限制内取更小值。

前台网络正常、平台不处于限流且无大附件时，少量结构化变更目标在 30 秒内完成一次往返同步。后台同步无固定延迟承诺。恢复点以最后一次成功云端提交为准，待上传本地数据在设备损坏时可能丢失。

支持系统字号至少放大到 200%、屏幕阅读器、明确焦点、按钮语义和非颜色状态提示。字号变化时卡片和表单自然伸展，不固定高度截断正文。

## 18 版本规划与开发安排

### 18.1 分阶段交付

| 阶段 | 建议时间 | 主要产出 | 退出条件 |

| 整体验证与试用 | 第 9 至 10 周 | 无障碍、性能、导出、问题修复 | 小范围持续试用与恢复演练通过 |

估算假设为 2 名研发全职，产品设计与测试各部分投入，总体约 26 至 34 人周，属于范围级工程估算，不是报价。阿里云盘申请等待、账号准入或补充审核可能独立延长日历时间；涉及多账号共享时必须重新估算。

若云盘多人成长数据场景未获准，可交付本地多档案与加密导出版本用于验证，但必须标明“云同步未开放”，不能以手动导出冒充已满足阿里云盘自动存储要求。用户指定云盘这一目标继续保留为待解决的产品依赖。

### 18.2 后续版本

V1.1 可增加 iOS 适配、桌面小组件、复盘报告样式和更多导入模板。V2 再考虑成员独立账号、邀请与授权、分人物加密共享、成员撤销和跨账号协作。

成员版需要明确身份认证、服务端强制权限、成员密钥分发和撤销策略。云盘分享链接不等于应用的成员权限；客户端隐藏按钮不能代替权限控制。是否需要协调服务取决于最终协作强度，并且不能未经用户同意改变成长正文存储在阿里云盘的要求。

AI 辅助可用于生成目标草稿、总结用户选择的复盘材料，但建议默认关闭；用户确认后才写入正式计划，模型输出不能自动修改成果值或把推断当事实。

## 19 完整使用示例

以下为职业技能领域的演示场景，与任何人的真实成长数据无关。

长期方向为未来五年具备独立负责芯片模块从需求到验证的能力。2026 年度目标为形成可复用的模块设计与验证方法，季度重点为交付一个模块并通过事先约定的验收清单。

该季度目标设置三个里程碑：需求与架构评审通过，权重 20%；RTL 与自测完成，权重 30%；验证与文档验收完成，权重 50%。前两项通过后成果进度为 50%。本周安排需求检查、测试补充和一次复盘等行动；行动完成率单独展示，不直接把“完成一次学习”折算成模块验收进度。

周末复盘发现验证任务持续延期，原因是依赖资料未齐。用户把下一周重点改为补齐接口约束，并调整里程碑日期，系统记录调整原因与版本。长期方向保持，阶段路径根据事实更新。

同时，管理者可为“家人A”建立阅读目标，为“家人B”建立生活习惯目标。首页分别呈现三个人的进展与下一步，各自采用适合的指标，不跨人物比较百分比。

## 20 设计决策与待验证事项

本方案已确定：多人卡片首页、四主导航、档案与账号分离、成果与行动分开统计、目标修订可追溯、本地优先、云盘保存加密业务副本、不可变增量日志与快照恢复。首版范围已满足多人信息管理，不依赖成员分别登录。

实施前需验证的关键事项为阿里云盘准入和多人物数据场景许可、获批应用的授权方式与权限、真实配额和限流、客户端加密库与系统安全存储适配，以及具体发布渠道要求。验证过程使用演示数据，并将结果写回接口规格与测试计划。

产品评审应重点检查首页是否能帮助用户找到下一步、长期目标是否能追溯到近期行动、指标是否准确反映成果、复盘是否引出可执行调整，以及用户能否在丢失设备后恢复已同步的数据。
