## 本次功能

| 要求 | 实现 | 使用方式与边界 |
| --- | --- | --- |
| 天空蓝界面 | 背景、按钮、导航、进度、状态栏及图标统一为蓝色体系 | 保留警告/错误的语义颜色，多人物头像仍有区分色 |
| 每人每日/每周/每月固定待办 | 复用独立行动与实例 ID，增加每条计划的提醒时间、固定计划快捷入口和按月完成历史 | 每周指定星期；每月指定日，短月没有该日则跳过；可暂停/恢复 |
| 到时提醒 | 原生 AlarmManager、通知渠道、按人物时区求下一次到期、开机/时间改变/升级后重算 | 可选准时提醒权限；没有权限时系统非精确调度；完成/暂停/归档/改期会重算，锁屏公开文案不含正文 |
| 记录完成情况 | 每个实例独立保留计划日期、完成时间、撤销日志，完成历史按计划月份筛选 | 不将行动投入自动当作目标成果 |
| 数据每天自动上传 OSS | 原生 JobScheduler 的持久、联网、24 小时周期任务，首次/漏备补试、手动触发、失败退避 | 用户必须配置真实私有 Bucket 和专用 RAM 凭据；Android 系统可延迟，强制停止后需重新打开 |
| 云端安全备份 | 独立恢复码、AES-256-GCM、OSS V4、Content-MD5、上传后 GET/SHA-256 校验 | 成功标记只在回读一致后更新；凭据及恢复码不进入业务备份；HTTPS 不跟随重定向 |

OSS 是“每天一份完整空间备份”，不是多设备实时同步或自动合并。各设备、各空间分目录，每台设备同日文件替换、历史日期保留。没有自动删除 OSS 文件；需要在控制台按自己的保留需求配置生命周期。恢复需要从控制台下载 `.gbp`，在 App 内输入对应恢复码、验证和预览后明确确认替换当前空间。步骤和最小 RAM 策略见 [OSS 接入与使用](OSS接入与使用.md)。

## 安全与可恢复性

Android 业务快照和 outbox 继续在同一 SQLite 事务内认证加密写入。本版修复多个后台/界面存储实例初始化时的 Keystore 密钥创建竞争；不会静默覆盖丢失密钥的已有数据库。OSS 配置使用另一把 Keystore AES 密钥和 AtomicFile，状态接口不返回 AccessKey Secret 或恢复码；恢复码仅在明确点击查看时返回到设置页。

备份在上传前用可恢复的独立 256 位密钥加密，和手动备份使用相同的 `.gbp` 格式/AAD，但恢复码单独管理。读取损坏配置时拒绝继续上传；用户可以明确移除本机配置后重设。移除、暂停均不会删除云端历史文件。没有把设备 Keystore 专用密文当作可换机恢复备份。

WebView 继续只加载 APK 内资源，CSP 禁止外部连接，网络只在原生备份模块发生；不支持任意用户输入的 URL，不关闭 TLS 校验，release 不开启远程调试。只有用户启用 OSS 后上传业务数据。

本机无 `/dev/kvm`，Android 15/AOSP x86_64 只能软件仿真。本版 WebView 124 的两个独立基础测试仍失败，见 [本次原始 XML](testing/v1.1.0/android-webview.xml)；上版历史结果另行保留。本次首次启动模拟器又出现系统网络栈退出、system_server 重启、包管理服务不可用，随后改用兼容 CPU 配置重试；兼容配置下重新安装成功，10 项 Android 平台测试全部通过，原始报告见 [平台测试 XML](testing/v1.1.0/android-platform.xml)。首次系统故障没有记为通过。

仍需在真实安卓设备或硬件加速模拟器上完成：安装/覆盖更新、APK 界面、通知点击/授权与到时触发、关机重启后提醒、跨日/断网重连后台备份，以及真实 OSS 权限拒绝/容量不足/撤销凭据/下载恢复测试。系统调度不存在固定整点或强制停止状态下执行保证。
